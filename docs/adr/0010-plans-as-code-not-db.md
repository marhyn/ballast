# Plans are a code-level config list, not a database table

`packages/billing/src/plans.ts` exports a static `Plan[]` (id, name, features, price IDs per provider) instead of a `plan` table. Pricing tiers change through a deploy, not through an admin UI, in the overwhelming majority of SaaS products this template targets — a DB-backed Plan would need an admin CRUD surface and a migration path for something that's really a compile-time constant. The `subscription` table still stores `priceId`, the one part of a Plan a webhook actually needs to persist; `getPlan()` maps it back to display data (name, features) at read time. A project outgrowing this (metered pricing, per-customer negotiated plans) should replace the config list with a real table rather than bend this one — that's a rewrite, not a migration, and this ADR is the flag that it was a deliberate simplification, not an oversight.
