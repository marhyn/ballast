# Platform admin: a plain User flag, not better-auth's admin plugin

`user.platformAdmin` (a nullable boolean, added via better-auth's `additionalFields` — see `packages/auth/src/index.ts`) gates the `/admin` oversight pages, checked by an `adminProcedure` on the API side (`packages/api/src/procedures.ts`) and an `admin` route middleware on the web side. better-auth ships its own `admin` plugin — user-level `role`/`banned`/`banExpires`, session `impersonatedBy`, and endpoints for banning, impersonating, and setting roles — but this template doesn't enable it. That plugin's `role` is a different, broader concept than what ADR-0009 asked for ("org/user/subscription oversight, gated behind a `platformAdmin` check") and would sit awkwardly next to the `organization` plugin's own per-org `member.role` (owner/admin/member) — two same-named-but-different "role" axes on the same user. A boolean is enough for read-only oversight; a project that needs ban/impersonate should adopt the admin plugin deliberately, not inherit it unused. `input: false` on the field means it can only be set by direct database access — no self-service promotion path exists, by design.
